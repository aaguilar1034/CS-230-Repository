# CS-230-Repository

# 1. Client and Software Requirements
The client for this project was The Gaming Room, which wanted to expand its game, Draw It or Lose It, into a web-based application that could support users on different operating platforms. The software needed to support multiple teams within each game and multiple players within each team. It also needed to prevent duplicate game and team names and use unique identification numbers for games, teams, and players. The design used object-oriented programming concepts to help organize the application and make it easier to maintain and expand.

# 2. What I Did Well
I think I did well at organizing the software design document and explaining how the different classes worked together. I included the Entity superclass, GameService class, and the relationships between games, teams, and players. I also compared different operating platforms and explained why Linux would be a good option for hosting the application. This helped me understand how to communicate technical decisions in a way that other developers and the client should follow.

# 3. What I found Helpful About the Design Process
Working through the design document before focusing on the code helped me understand the requirements and plan how the application should work. Creating the domain model helped me see how the classes were connected and what responsibilities each class should have. Having this plan made it easier to organize the code and understand how concepts such as inheritance, encapsulation, and the Singleton pattern could be used in the application.

# 4. What I Would Revise
If I could revise one part of my work, I would improve the system architecture explanation and provide more details about how different parts of the application would communicate. I would also include a clearer explanation of how the application could handle more users as it grows. This would make the design more complete and help developers better understand how the application could work in a real-world environment. 

# 5. Understanding the User's Needs
I interpreted the client's needs by focusing on the game's requirements, including supporting multiple teams and players, preventing duplicate names, and allowing the application to work across different platforms. I used these requirements to guide the design and choose appropriate programming concepts. Considering the user's needs is important because the software must solve the problem the client actually has. Without understanding those needs, developers could create an application that works technically but does not provide the features or experience the client expects.

# 6. My Approach to Software Design
My approach to software design was to review the requirements, identify the main classes and their responsibilities, and determine how the classes should interact. I used object-oriented programming concepts to organize the application and considered the advantages and disadvantages of different operating platforms. In the future, I would continue using these strategies while also creating diagrams, checking requirements throughout development, and testing the application as I build it. I think planning ahead and reviewing the design regularly can help reduce errors and make software easier to maintain.
